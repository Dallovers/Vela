# 比赛演示流程

## 当前 0.2.0 演示（优先使用）

1. 展示新对话页、“给助手发消息”输入栏和“本机 · 已连接”。点“看看屏幕”并发送，展示读屏回复。此流程仍通过手机任务执行器完成，不称为独立自由聊天。
2. 设置 → 手机操控 → 试一下本地练习 → 多任务问答与恢复自测。说明这是确定性注入的问题，用来验收暂停与恢复。
3. 自己输入一段测试文字，点“回复并继续”，展示输入后再模拟发送，计数只增加 1。返回助手，展示同一会话的问题、自由回复和两项结果。
4. 点标题/进度查看步骤，展示暂停/继续；展示已经录制的排队与草稿保留证据。未现场运行的内容明确称为验收录像或截图。
5. 展示 0.2.0 报告：44 项单元测试、lint 0 errors/7 条 KTX 建议。本次只在一台 OPPO 上做限定测试，不承诺任意应用可靠性。
6. 展示 43 类 DSH 功能对照和 P1–P5 路线。终端、文件、远程电脑、插件、机器人和桌宠均在范围内，尚未实现。

下面是历史版本流程，入口以当前页上方为准。

## 建议演示顺序（约 3 分钟）

1. 展示“任务”页和 OPPO Find X9s Pro，说明这是实际安装运行的安卓应用。
2. 进入“调试 → 打开定位练习”。强调练习的发送按钮只增加本机计数，不会发送网络消息。
3. 点击“运行一次定位自测”，展示助手识别输入框、填入“定位测试”、通过 OCR 识别无障碍树不提供的发送按钮，并把本地计数加到 1。
4. 展示任务步骤日志中的 N 原生目标和 V OCR 目标，以及点击前重新复核结果。
5. 展示验收报告：32 项自动测试通过、微信搜索输入真机验证通过；指出真实消息发送没有纳入验收。
6. 展示后续产品原型方向：一个会话中多个任务、可编辑步骤和模型犹豫时的澄清对话框。这些页面/能力尚待下一阶段实现，除非新版本另有验收证据。

## 演示前检查

- 确认手机电量、USB 连接、无障碍服务连接和模型网络。
- 手机停在助手首页；确认 `artifacts/apk/current/` 中的版本与本次演示版本一致。
- 用本地练习先演示一次，不对真实聊天发消息或拨打电话。
- 将“记录”页截图用于展示前检查，确认没有 API key、聊天预览、联系人或私密测试文字。
- 本地 OCR/模型偶尔耗时，演示时不要重复点“运行”，等待当前任务结果；若失败，使用报告中标明的练习截图并明确说明为已录制证据。

## 现场失败预案

如果模型接口或网络不可用，停止任务并展示已归档的本地练习截图与去敏日志，说明现场网络依赖。不能把截图伪装成当前运行，也不要切换到真实聊天任务冒险演示。


## 0.1.8 开发版补充

使用 0.1.8：调试 → 定位练习 → 多任务问答与恢复自测，展示确定性歧义问题，输入 ResumeTest 或选候选文字，提交后观察输入与一次本地模拟发送。练习计数仅本地变化。进程中断后展示“已暂停”，继续前重新截图。证据见 reports/acceptance/v0.1.8/evidence。确定性提问须说明是验收注入，不能称为模型自主发现。


0.1.9 界面入口更新：左上“会话”打开侧栏并新建；底部输入目标、创建计划；“计划”页调整步骤，“上下文”页管理记忆。右上设置进入“手机控制”，练习入口仍在其中。开启服务后再安排本地练习，0.1.9 本轮仅复验页面交互。
