# 安卓手机 AI 助手项目计划

更新日期为 2026 年 11 月 17 日。

## 项目目标

制作一个安装在 OPPO Find X9s Pro 上的安卓 App。用户输入任务后，App 获取屏幕画面，调用视觉模型判断下一步，通过安卓无障碍服务执行操作，再检查执行结果。

开发、构建与文档的项目根目录设为 E:/AndroidPhoneAgent。

当前按个人自用、单台 OPPO 真机、现成视觉模型 API 来规划。手机上实际安装的 Android 版本和 ColorOS 版本在首次连接调试时记录。模型服务地址、模型名称和 API key 在手机上配置。

第一个验收任务暂定为“从桌面打开设置，进入关于本机页面”。这是便于观察执行结果的初始练习，后续可以按用户的实际任务调整。

## 技术路线

### 安卓 App

使用 Kotlin 编写，界面采用 Jetpack Compose。首轮以简单的输入框、配置项、状态提示和操作按钮支持调试。

截图优先使用 AccessibilityService.takeScreenshot。该接口从 Android 11 开始提供，服务需要声明截图能力，并由用户启用无障碍服务。点击、长按和滑动使用 dispatchGesture，返回和回桌面使用全局动作，文字填写使用可编辑控件支持的 ACTION_SET_TEXT。截图存在调用间隔与受保护内容等约束，需要在真机上检查。[无障碍服务官方接口](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)

MediaProjection 作为截图兼容方案，在真机验证表明有需要时引入。它涉及每次采集会话的用户授权和相应的前台服务配置。[屏幕采集官方说明](https://developer.android.com/media/grow/media-projection)

### 模型调用

接入支持图片输入、兼容 OpenAI 聊天请求格式的模型服务。请求包含用户目标和当前截图，模型返回约定格式的下一步动作。接口能力和模型输出格式通过连接测试确认。

每轮执行按以下顺序进行。

1. 获取当前屏幕截图，并记录尺寸和方向。
2. 将目标和截图发送给视觉模型。
3. 解析并检查动作类型、坐标和必要参数。
4. 执行一个动作，等待系统完成手势和页面更新。
5. 重新截图，结合后续模型判断检查进展。
6. 完成、停止或发生需要用户处理的异常时，更新任务状态。

截图尺寸、系统栏和屏幕方向参与坐标换算。方向或尺寸变化时刷新画面和坐标信息。每个任务保留当前运行标识，停止后到达的旧模型回复应被忽略。网络重试针对模型请求处理，已经执行的动作先检查结果，再决定下一步。

### 任务反馈

显示准备中、读取屏幕、分析中、执行中、已完成、已停止和异常等状态。运行中提供便捷的停止入口，具体入口形式在真机验证中确定。记录步骤、耗时和错误原因，方便根据真实现象修复问题。

模型密钥通过 Android Keystore 支持的本地加密方式保存。日志采用排除密钥和授权请求头的字段设计。截图随任务需要在手机本地管理，并提供清理入口。

## 分阶段交付

### 阶段一，构建并运行基础 App

检查本机已安装的软件，按构建兼容关系选择并固定 JDK、Android SDK、Gradle 与 Android Gradle Plugin 版本。搭建可复现构建的 Kotlin 安卓工程，将 SDK、下载文件、项目缓存和 APK 产物放在 E 盘指定位置。

交付一个基础 APK，用户在 OPPO 上确认安装和启动。记录实际系统版本和安装过程中出现的提示。

### 阶段二，真机验证截图和操作

实现无障碍服务、权限引导、截图预览和手动操作验证。先在练习界面验证坐标，再验证系统设置页面，记录导航方式、显示缩放和屏幕方向对坐标的影响。

交付能够在 OPPO 上获取截图并完成基础动作的 APK。截图和动作的兼容性结果决定后续适配工作。

### 阶段三，接入 AI 并跑通一个任务

实现模型配置、连接测试、图片请求、动作解析与逐步执行。完成暂定的设置页面任务，并展示每一步的动作和结果。

交付能够完成首个连续任务的 APK，以及对应的真机执行记录。

### 阶段四，改善重复使用的稳定性

处理网络超时、权限撤销、服务中断、页面加载、重复动作和停止时的并发状态。根据 OPPO 的实际运行表现调整后台运行方案。反复运行演示任务并记录成功率、失败位置和模型响应时间。

交付经过多次真机验证的原型、简明安装步骤和已知问题记录。

## 验证方法

构建通过、安装成功、动作可用和任务成功分别记录。对模型建议完成的任务，检查实际手机页面是否到达目标位置。

连续任务验证时记录起始页面、模型名称、执行步骤、是否成功及失败原因。停止验证覆盖模型请求中、等待页面中和动作执行后的情况。网络异常恢复后先获取最新画面，再继续判断。

手机端验证进度见 artifacts/VALIDATION.md。个人自用原型的运行结果与后续多机型适配进度分别记录。

## E 盘目录安排

以下目录在对应开发步骤中创建。

| 路径 | 内容 |
| --- | --- |
| E:/AndroidPhoneAgent/app | 安卓 App 源码 |
| E:/AndroidPhoneAgent/gradle | Gradle Wrapper 配置与构建入口相关文件 |
| E:/AndroidPhoneAgent/tools | 项目使用的 JDK、Android SDK 等工具 |
| E:/AndroidPhoneAgent/cache | Gradle、Android 用户目录等可配置缓存 |
| E:/AndroidPhoneAgent/artifacts | 构建后的 APK 与真机验证记录 |
| E:/AndroidPhoneAgent/work | 下载包、临时文件和调试中间产物 |
| E:/AndroidPhoneAgent/PROJECT_PLAN.md | 项目计划和阶段进度 |

后续构建入口统一配置 JAVA_HOME、ANDROID_HOME、ANDROID_USER_HOME、GRADLE_USER_HOME、TEMP 与 TMP 指向项目内的 E 盘位置。采用项目级环境配置，让构建过程可以复现。操作系统、驱动与手机安装文件按各自系统机制管理。
