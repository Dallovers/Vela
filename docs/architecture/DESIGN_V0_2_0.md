# 0.2.0 对话与手机操控

本轮按 DSH Go 1.2.0 真机体验和固定版本源码，用 Kotlin/Compose 独立实现第一阶段交互。完整产品范围及未完成项见 `../roadmap/DSH_FULL_PRODUCT_PLAN.md`，不能把这个版本称为完整复刻。

## 参考与设计

实际体验了 DSH 的首次权限页、登录后首页、展开输入、无工具问候及回复、标题详情、侧栏、全部功能、手机操控及确认方式弹层。权限设置和确认模式仅查看，没有开启 DSH 的手机操作，也未运行其终端、远程电脑或机器人。参考 composer、chat_header、chat_dock、empty_state、feature_catalog、phone_control_screen 和中文资源；没有复制 Flutter 源码、品牌图标或宠物资源。

聊天作为主屏：顶部对话标题与本机连接状态，中间消息，底部输入栏；新对话显示问候和四个可用建议。默认输入栏单行，聚焦或有草稿时显示模型入口。标题和底部进度打开接近全屏的详情，包含进度与记住的信息；任务表单不再常驻主屏。侧栏提供历史、搜索和状态筛选，关闭后清除搜索焦点并收起键盘。手机操控把连接和练习放前面，基础动作测试折叠。

使用系统中文字体与动态字号，保留 48 dp 图标触区；独立 Canvas 线性图标带可访问名称。浅色基底 #F4F6FB、正文 #202634、主色 #4965AC；暗色基底 #202635、表面 #2A3141、正文 #E7EAF2、主色 #A4BCF8。颜色遵循语义 token，系统暗色同步到练习页。文案统一为“新对话 / 给助手发消息 / 发送 / 继续 / 暂停 / 等你回答 / 记住的信息”。

## 状态和数据

- 会话 schema 2 新增真实消息与提示；兼容读取 schema 1。旧会话只根据已有目标和已完成结果展示，不伪造中间回复。未来 schema 拒绝写入，原文件保留。
- 一次发送是一项请求，换行仍在同一条消息中。运行时添加到队尾，不重写正在执行的任务；第一项结束后循环读取最新队列。它是排队，不是即时插话。
- 未连接服务或模型配置缺失时保留用户消息，显示可继续的提示。用户主动暂停后再发送也只保存，需点击“继续”。另一会话运行时不会抢占执行器。
- 问题绑定会话、任务与 question id；发送栏在待答时提交自由回答。答复记入当前会话，重新截图后恢复；旧问题或重复答复无效。
- 草稿按会话和 question id 分开保存到应用私有 SharedPreferences；新对话有独立草稿。发送成功后清除来源草稿，删除会话时清除对应草稿。密钥仍由原有 Keystore 设置存储负责。
- 一个运行 Job 和 generation 仍负责取消。重启恢复为暂停/待答，不自动执行，不重发旧坐标。UI 消息保留，模型上下文仍采用有界摘要和近期任务结果。
- 等待动作回传实际等待时长，避免仅见相同画面而反复等待。该改动不能保证模型永不重复，应结合进展保护和用户暂停。

## 当前边界

这是手机任务执行器上的聊天交互，不具备独立的无读屏自由聊天模式；每项请求仍要求本机服务和当前屏幕。模型回复暂为整段返回，不是 token 流。已有回复复制；分享、朗读、分支、重试、即时插话、文件夹和归档继续列在 P1。应用名单和每动作确认等手机权限策略尚未实现。文件、终端、本机 Linux、远程电脑、插件、机器人和桌宠按后续阶段推进，未放无效入口。
