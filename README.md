## 安装和首次验证

1. 把 E:/AndroidPhoneAgent/artifacts/apk/current/PhoneAgent-0.3.5-debug.apk 复制到手机并打开，按手机提示完成安装。
2. 打开“Vela” → 左侧菜单 → 手机操控 → 打开系统无障碍设置 → 已下载的应用 → Vela 操作服务。启用后返回助手，确认“本机 · 已连接”。服务会获取屏幕，并按你发送的任务执行操作。
3. 若系统提示应用受到受限设置保护，按系统提供的应用详情入口完成允许，再回到无障碍设置启用服务。
4. 返回 App，确认顶部显示“操作服务已连接”。
5. 在“调试”页先测试“获取当前截图”和“打开系统设置”，再验证点击、滑动、返回和回桌面。操作动作延迟 2 秒，方便切换到练习页面。
6. 文字填写测试需要先在目标 App 点击输入框并弹出键盘，再等待动作执行。Android 13 及更新系统在控件不可见时可使用输入连接填写文字，填写后会读回核对；已有文字会先全选再替换。

输入方式按当前界面选择：普通输入框使用控件或系统输入连接；拨号盘、数字键盘使用按键点击。数字按键通过完整键盘区域的标签定位，无法定位时让模型根据截图选择点击位置，不需要逐个配置 App。若文字尚未提交就发现输入方式不可用，助手会把失败结果交回模型，重新选择操作；若文字已提交却无法确认结果，则停止并提示核对。

## 配置模型

在“模型”页填写服务接口地址、支持图片输入的模型名称和 API key。接口地址填写到服务的 API 基础路径，例如服务提供的 https 地址加 /v1。完整的 /chat/completions 地址也可使用。本地部署服务可以填写对应的 http 地址。

点击“保存配置”，再点击“测试图片请求”。测试会向所配置的服务发送一张小测试图片，并检查是否收到回复。API key 在手机本地通过 Android Keystore 支持的加密方式保存。

使用 DeepSeek 官方服务时，可填写 https://api.deepseek.com 和模型名 deepseek-flash，密钥直接在手机上填写。该模型当前支持图片输入，详见[官方图像理解说明](https://api-docs.deepseek.com/zh-cn/guides/vision/)。

当前 DeepSeek 官方将 deepseek-flash 对应到 V4.1-Flash-1017。根地址与带 /v1 的基础地址均已通过账号模型列表实测。若 OPPO 安全键盘限制长按粘贴，可使用密钥框右侧的“粘贴”按钮，App 会填入剪贴板文字并保持遮挡显示，再点击“保存配置”。

## 执行任务

在对话输入栏直接发消息，例如“打开设置，进入关于本机页面”。运行中补充要求可选“改做这件事”立即替换当前任务，或“做完再处理”排队；助手会重新观察再继续，已执行操作不会自动撤销。

运行时，屏幕上显示“停止任务”按钮。App 内也提供停止按钮。停止操作会取消网络请求和后续待执行动作，已经交给系统的手势由系统结束。

OPPO 屏幕边缘的绿色手机图标是系统无障碍快捷开关，点击可能关闭整个操作服务。结束当前任务请使用红色“停止任务”按钮；若误关服务，需重新在系统设置中开启。

模型判断任务完成时，App 显示“模型报告完成，请查看结果”。通过手机实际页面和最近截图检查结果。“记录”页显示当前应用进程内的步骤和错误信息。

翻页可直接让助手向上或向下滚动。scroll 动作只需方向，执行器在当前应用区域生成滑动手势，并避开系统栏和键盘；调试页提供“向下翻页”和“向上翻页”按钮。down 表示查看下方内容，手指向上滑；up 表示查看上方内容，手指向下滑。原 swipe 坐标动作仍可使用。

DeepSeek 官方接口的动作请求使用[指定函数工具调用](https://api-docs.deepseek.com/zh-cn/guides/tool_calls/)，每次只接受一个 phone_action 调用。按官方要求关闭该动作请求的思考模式，读取工具参数后再进行本地动作校验。其他兼容服务仍可返回单个 JSON 动作。空回复、缺字段、无效坐标、不完整 JSON 或多个动作都不会执行，会将具体分类交回模型重试，连续 3 次无效动作后停止。已成功执行的动作不因格式重试而重放。“记录”页显示错误分类，诊断摘要只记录返回方式、结束原因、字符数和动作类型，不输出原始回复或密钥。

0.1.7 每次截图会生成一个屏幕编号，同时读取系统控件和本地中英文文字识别结果。模型优先选择当前画面的目标编号；点击前重新截图，检查应用、键盘状态、目标文字和位置。旧画面中的目标失效时拒绝点击并重新观察。文字识别框不代表一定可点击，模型仍需结合画面区分按钮和聊天文字。没有文字的图标使用坐标网格辅助定位；画面变化时拒绝旧坐标。

连续 3 次点击后内容未变化，或最近 12 次观察中同一可识别页面状态出现 4 次，会停止任务并提示检查进展。它们是防止重复操作的启发式检查；任务确实需要重复同一页面时也可能提前停止。没有可识别文字的画面不适用这项页面状态检查。

“调试 → 打开定位练习”可运行本地自测。模型填写“定位测试”并点击发送，成功时显示“已模拟发送 1 次”。按钮只更新本地计数，可检查原生输入框和文字识别按钮的定位。参考设计及区别见 [docs/architecture/DESIGN_REFERENCES.md](docs/architecture/DESIGN_REFERENCES.md)。

## 本机构建

项目使用 Kotlin 2.1.20、Compose BOM 2025.04.01、Android Gradle Plugin 8.9.2、Gradle 8.11.1、JDK 21，以及 Android SDK Platform 35 / Build Tools 35.0.0。最低系统版本为 Android 11。

在 PowerShell 中运行项目根目录下的 build.ps1。构建入口把 JDK、SDK、Gradle 用户缓存、Android 用户目录和临时文件配置到项目内的 E 盘路径。源码位于 app/src/main，构建后的 APK 复制到 artifacts/apk/current；构建新版本时旧版移至 artifacts/apk/archive。开发辅助脚本在 scripts，临时文件与下载包在 work。

执行 assembleDebug、testDebugUnitTest、lintDebug 可以检查编译、动作解析和静态问题。相关报告位于 app/build/reports。

## 真机调试

用数据线连接手机，在手机开发者选项中启用 USB 调试，并确认电脑授权。ADB 位于 E:/AndroidPhoneAgent/tools/android-sdk/platform-tools/adb.exe。连接后可以安装 APK、检查运行日志和截取实际界面。

## 0.1.8 会话开发版

“会话”页创建标题、目标和逐行步骤，保存/移动/删除尚未执行的步骤，运行期间可添加后续步骤。所有子任务从当前页面继续；开始前请打开目标页面。用户摘要可检查、修改和清除，任务结果作为模型观察展示。

本地演示：调试 → 打开定位练习 → 多任务问答与恢复自测 → 选项或输入自定义文字 → 提交后重新观察 → 两步完成一次本地模拟发送。暂停后可在练习页继续；重启不会自动执行。待答通知可在调试页主动启用，未授权时回到会话查看问题。

实现范围和限制见 [会话架构](docs/architecture/SESSION_V0_1_8.md)。真实发送、付款等外部动作及全面风险询问策略尚未验收。
